# DSH 插件 README 写作规范

> 给 coding agent 写 DeepSeek Harness 插件 README 时照做的章节模板与写作规则。提炼自 `dsh-grill-me` 成品 README，并对照 DSH 仓库内包 README 的风格。

## 0. 语言与篇幅

- 独立插件项目：中文为主，命令、工具名、标识符保留英文。
- 仓库内包：英文为主，一段话简介 + 分节 + 表格。
- 独立插件 README 控制在 150–400 行；超过说明在堆砌实现细节。

## 1. 结构模板

| 顺序 | 章节 | 写什么 | 不写什么 |
| --- | --- | --- | --- |
| 1 | 简介 | 一句话价值 + 3–5 条核心特性 | Roadmap、致谢 |
| 2 | 工作原理 | 能力接缝表格 + 数据流一句话 | 架构大图、贴源码 |
| 3 | 工具一览 | 表格：工具名 + 作用 | 参数 schema 全量 |
| 4 | 安装 | 命令 + 生效时机 + 从源码构建 | 构建链内部原理 |
| 5 | 配置 | 配置项表格 + YAML 示例 | 每个配置的源码出处 |
| 6 | 使用协议 | 可执行的步骤清单 | 完整对话脚本 |
| 7 | 验证 | 离线 / 组合 / 真实 e2e 三层 | 把"未验证"写成"已验证" |
| 8 | 已知限制 | 每条 = 现象 + 原因/影响 + 缓解 | 无缓解的抱怨 |
| 9 | 文档 | 指向详细指南的表格 | 重复正文 |
| 10 | License | 许可证名 | — |

## 2. 工作原理怎么写

开篇用能力接缝表格（DSH 的架构语言——一切皆插件、能力即接缝）：

```markdown
| DSH 能力 | 插件用法 |
|---|---|
| `ctx.tools` 注册表 | 注册 N 个 `xxx_*` 工具 |
| `ctx.systemPrompt.section()` | 注册协议段 |
| 文件系统 | 状态持久化在 `<workspace>/.xxx/<id>/` |
```

表格后补数据流一句话，如"工具执行 → 磁盘状态（真相源）→ 会话日志事件（审计/重放）"；需要展开的细节放文件引用，不贴代码。

## 3. 安装与配置

- 安装命令必须可复制：绝对路径或明确 cd；说明"插件 add 后需要重启 profile"。
- 配置节用表格 + YAML 示例；兼容性/部署差异用引用注释块，正文保持干净。

## 4. 验证章节规范

分层 + 诚实标注"已验/待验"：

- 离线：`pnpm typecheck && pnpm build && pnpm verify`，说明覆盖面。
- 组合：`dsh plugin --profile headless add .` + `--dump-config`。
- 真实 e2e：给出 headless 命令与落盘/事件核对点；注明需要 `DEEPSEEK_API_KEY`。

## 5. 已知限制怎么写

每条限制 = 现象 + 原因/影响 + 缓解，一条 bullet 内说完。写真实限制而非套话：文件级持久化、单进程串行、模型不守仪式、私有仓库分支保护限制等。

## 6. 完成检查清单

- [ ] 简介一句话回答了"装了这个插件用户能做什么"
- [ ] 工作原理以能力接缝表格开头，数据流一句话
- [ ] 工具、配置、协议、验证、限制齐全
- [ ] 安装命令可直接复制，并写明生效时机
- [ ] 验证分层，未验证的明确标出
- [ ] 已知限制每条含缓解路径
- [ ] 没有贴源码、没有架构大图
